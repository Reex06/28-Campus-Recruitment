一个纯静态的在线学习打卡表格，用于监督自己的嵌入式学习进度，目标是 **2027 年 8–9 月 28 届秋招**。

- ✅ 大模块 + 小模块的层级结构

## 权限模型（重要，先看这里）

这个页面是**纯静态**的，所以「谁改」「谁看」是这样分工的：

| 角色 | 能看到/能做什么 | 靠什么保证 |
|------|----------------|-----------|
| 访客 | 打开公开网页，**只能看**，不能改 | 公开网页 `index.html` 是纯只读的，没有任何可改数据/密码的入口 |
| 你 | 在本机 `edit.html` 里改进度，再推送上 GitHub | `edit.html` 存在你自己电脑上（已被 `.gitignore` 排除，不会上传）；推送需要你的 GitHub 账号权限，别人推不了 |

> 所以这里**没有**「网页上输密码就能改」的机制了——密码不再暴露在任何公开文件里，安全性由 GitHub 账号登录来保证。

## 日常打卡 + 同步流程（每次改进度做一遍）

1. 本机打开 `edit.html` → 解锁编辑 → 修改状态/进度/时间（改动会自动存到本机浏览器）。
2. 改完点右上角 **「📦 导出 data.js」**，下载一个 `data.js` 文件。
3. 用下载的 `data.js` **覆盖本目录里的 `data.js`**。
4. 运行部署脚本（在 `打卡` 目录下）：
   ```bash
   ./deploy.sh
   ```
   或手动：
   ```bash
   git add index.html data.js && git commit -m "更新打卡进度" && git push
   ```
5. 等约 1 分钟，刷新线上页面，访客就能看到最新进度。

> 💡 `deploy.sh` 已经只提交 `index.html`、`data.js` 等，**不会**把 `edit.html` 推上去（`.gitignore` 已排除）。你的密码和编辑页始终留在本机。

## 部署到 GitHub Pages（首次）

### 方法一：网页端（推荐，最快）

1. 登录 GitHub，新建仓库 `learning-checkin`，选 **Public（公开）**。
2. 「uploading an existing file」上传：`index.html`、`data.js`、`.nojekyll`（**不要**上传 `edit.html`）。
3. **Settings → Pages** → Source 选 `Deploy from a branch` → 分支 `main` → 目录 `/ (root)` → Save。
4. 等 1 分钟左右，访问 `https://你的用户名.github.io/learning-checkin/` 即只读展示页。

### 方法二：命令行

本机已装 Git 的话，直接跑：

```bash
cd "C:\Users\20321\Desktop\27秋招\打卡"
./deploy.sh
```

`deploy.sh` 会初始化仓库、提交并推送；之后只需去 Settings → Pages 里开启 Pages（同上第 3 步）。

## 为什么这样比「网页上输密码」更安全

原来 `index.html` 里直接写死了 `PASSWORD`，任何人打开公开网页都能右键查看源码拿到密码，从而篡改你的进度（纯前端无法真正隐藏密码）。现在：

- 公开网页上**没有任何密码**，只有只读展示；
- 你的编辑页 `edit.html` 只在**你自己电脑上**，不会上传；
- 「改」这一动作由 **GitHub 账号权限**把关，别人无法 push，也就无法改你的进度。

代价只是：每次改进度后你要走一次「导出 → 覆盖 data.js → 运行 deploy.sh」，多两步手动操作——换来的是真正的安全。
